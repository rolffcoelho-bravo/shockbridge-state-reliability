# Support

## Research and reproducibility questions

Use the repository's structured issue forms:

- **Reproducibility report** for an unexpected command result, evidence-skip
  count, environment mismatch, or hash discrepancy.
- **Bug report** for a deterministic software defect with a minimal reproducer.

For a scientific claim, identify the exact claim, table, figure, protocol, or
ledger entry and explain what evidence appears inconsistent. Questions about
the state-measurement result are welcome; requests to infer transmission
effects from the released measurement evidence are outside its validated
scope.

## Security reports

Do not open a public issue for suspected vulnerabilities, leaked credentials,
or sensitive paths. Follow `SECURITY.md` and use GitHub private vulnerability
reporting.

## Data requests

The project uses real, freely retrievable official sources, but it does not
redistribute raw or processed datasets. Use the identifiers and retrieval
metadata in `data/manifests/` and `docs/data/`. Third-party rights and source
terms remain with their owners.

## Response boundary

This is an independent research repository, not a service-level support
channel. Reports with a reproducible example and a precise evidence reference
are prioritized. Never post personal data, API tokens, credentials, or
protected research artifacts.
